# Brief 0008 — `boundary`: reserved-literal stop strings, stream fallback, receipt-side trim
Status: implemented
Complexity: high
PLAN sections: §8 (generation must be terminated before the model can commit the external character's block; the stop is keyed to the reserved tag syntax itself — bare `Mara:` — not `\n\nMara:`, because the name may be the first token sequence of a generation), §14 "External-character boundary" (the collaborator receives the floor) and "Empty output at the boundary" (the model tried to place the external character immediately; the floor stays with the collaborator; do not force model text merely to avoid an empty generation), §15 (the collaborator may insert the external character at any valid block boundary; the stop sequence is one trigger for external authorship, not the sole permission mechanism)
Invariants touched: INV-2 (the model cannot generate the externally owned character's committing tag — this module is its owner), INV-8 (named only to be refused here: rolling back an incomplete trailing block belongs to `recovery`, not to this brief)

## Goal
`src/boundary.js` exists and makes INV-2 hold at three points in one generation: the request body carries the reserved literal `<persona>:` as the first stop string on both the chat- and text-completion paths; a streaming backend that ignores stop strings is stopped from `STREAM_TOKEN_RECEIVED` the moment the literal appears at a block start; and any received non-user message that still contains the literal at a block start is trimmed back to the character before it, marked, and saved. The literal is computed fresh from the live context on every use and is never stored, never configured, and never written into `src/constants.js` or metadata. `index.js` gains only the subscriptions that drive those handlers.

## In scope
- Create `src/boundary.js` exporting four pure helpers. "Pure" here means: no host access, no module state, no I/O; `applyStopStrings` mutates only the body object it is handed, because that object is the live event payload.
  - `reservedLiteral(ctx)` → string. Computes `${name}:` where `name` is `ctx.substituteParams('{{user}}')` trimmed; if `substituteParams` is missing, throws, returns a non-string, returns an empty string, or returns the unexpanded macro text `'{{user}}'`, fall back to `String(ctx.name1 ?? '').trim()`. If the resulting name is empty, return `''` — an empty persona name is legal (`docs/modules/bootstrap.md#capability-gate` keeps `name1: ''` valid) and a bare `':'` literal must never be installed or matched. Never cache the result across calls; `getContext()` captures `name1` by value (`docs/api/sillytavern.md#getcontext`).
  - `applyStopStrings(body, literal, api)` where `api` is `'chat' | 'text'`. No-op when `literal` is empty or `body` is not an object. For each target field (`'stop'` for `'chat'`; `'stopping_strings'` and `'stop'` for `'text'`): if the field is not an array, set it to `[]`; remove every element strictly equal to `literal`; `unshift(literal)`. Net effect: the literal is at index 0 exactly once, existing entries keep their relative order, and a second call is idempotent. Returns `body`.
  - `findBoundary(text, literal)` → `{ index, endsAtLiteral }`. Derives the actor by stripping one trailing `:` from `literal` and calls `findTagLiteral(text, actor)` from `src/grammar.js`; `index` is the `index` of the first returned occurrence with `atBlockStart === true`, or `-1` when there is none. `endsAtLiteral` is `true` only when `index !== -1` and `text.slice(index + literal.length).trim() === ''`. No-op shape (`{ index: -1, endsAtLiteral: false }`) when `text` is not a string or `literal` is empty.
  - `trimAtBoundary(text, literal)` → string. Returns `text` unchanged when `findBoundary().index === -1`; otherwise `text.slice(0, index)` with trailing whitespace stripped (`.replace(/\s+$/, '')`, matching `truncateToLastCompleteBlock`'s convention in `src/grammar.js`). The result may legitimately be `''`.
- In the same module, five event handlers plus a test seam. They may import `getCtx` from `src/host.js` and call it fresh on every invocation; they must never name the ST global (`tests/bootstrap.test.js` asserts that identifier appears nowhere outside `src/host.js`).
  - Module state: `currentType` (string | undefined), `currentDryRun` (boolean), `stoppedThisGeneration` (boolean). `resetBoundaryState()` is exported for tests only.
  - `onGenerationStarted(type, _options, dryRun)` — records `currentType = type`, `currentDryRun = Boolean(dryRun)`, and sets `stoppedThisGeneration = false`. Payload shape per `docs/api/sillytavern.md#generation-started`.
  - `onChatCompletionSettings(body)` / `onTextCompletionSettings(body)` — return immediately when the generation is skipped by the type rule below or when `currentDryRun` is true; otherwise `applyStopStrings(body, reservedLiteral(getCtx()), 'chat' | 'text')`. Neither event carries a type or a dryRun flag (`#chat-completion-settings-ready`, `#text-completion-settings-ready`), which is why the type is tracked from GENERATION_STARTED. The dryRun guard is defensive only: `#body-assembly` shows a dry run returns before CHAT_COMPLETION_SETTINGS_READY fires.
  - **Generation-type rule (decided here, applies to all three handlers).** Inject/act for every generation except `type === 'quiet'` and `type === 'impersonate'`; MESSAGE_RECEIVED additionally skips `type === 'first_message'`. Rationale, from `#generation-types` (`'normal' | 'continue' | 'regenerate' | 'swipe' | 'quiet' | 'impersonate'`) and PLAN §8, which constrains what the model may *commit in the manuscript*: a `quiet` generation is an out-of-band prompt whose output never becomes a manuscript block, so INV-2 has nothing to protect there and a persona-named stop would silently truncate unrelated utility output; an `impersonate` generation is ST writing the collaborator's own turn, so its output is *supposed* to be the persona's text and our literal would terminate it at once (ST's own stopping strings already carry names on that path, `#stop-text-completion`). Every other value, including an unknown one or a missing one (no GENERATION_STARTED observed — `#generation-started` notes ST can skip follow-up events), is treated as in scope: INV-2 fails closed. `'append'`/`'appendFinal'` are `saveReply` types, not `Generate` types, and need no rule.
  - `onStreamToken(text)` — returns when the type rule skips, when `stoppedThisGeneration` is already true, or when `reservedLiteral(ctx)` is empty. Otherwise, if `findBoundary(text, literal).index !== -1`, set `stoppedThisGeneration = true` and call `ctx.stopGeneration()` exactly once. `text` is the cumulative text so far and is not mutable (`#stream-token-received`); the stop lands on the next chunk and the partial text is kept as the message (`#stopgeneration`), which is precisely why the receipt-side trim below is not optional.
  - `onMessageReceived(index, type)` — skips when `type` is `'quiet'`, `'impersonate'` or `'first_message'`; unknown and `undefined` types are processed (`#message-received`: do not discard unknown types). Reads `message = ctx.chat?.[index]`; returns when it is not an object, when `message.is_user` is truthy, or when `message.mes` is not a string. Returns without writing or saving when `findBoundary(message.mes, literal).index === -1`. Otherwise: `message.mes = trimAtBoundary(message.mes, literal)`; if `Array.isArray(message.swipes)` and `message.swipes[message.swipe_id] !== undefined`, assign the same string there (`#message-shape`); set `message.extra = message.extra ?? {}` and `message.extra[METADATA_KEY] = { ...(message.extra[METADATA_KEY] ?? {}), boundary: true }` so `recovery` and `capture` can later read that the floor passed to the collaborator at this message; call `ctx.updateMessageBlock(index, message)` unconditionally (signature `updateMessageBlock(messageId, message, { rerenderMessage = true } = {})`, synchronous, renders from the object it is passed, emits no event — `#updatemessageblock`); `await ctx.saveChat()`.
  - **Why the `updateMessageBlock` call is unconditional.** The two receipt paths differ (`#edit-on-receipt`): on the non-streaming path MESSAGE_RECEIVED fires *before* `addOneMessage`, so editing `.mes` alone already produces the right DOM and `updateMessageBlock` is a silent no-op (no node carries that `mesid` yet); on the streaming path the message is already painted, and the call is the only thing that repaints it. One unconditional call is correct on both paths, so the module does no path detection and reads no streaming state.
  - **Empty output at the boundary (§14).** If the trim yields `''`, write `''` to `mes` (and the swipe), set the marker, re-render and save. Do not delete the message, do not substitute placeholder text, do not re-trigger a generation, do not roll back to the previous block. The floor is the collaborator's and an empty model turn is the correct record of that.
- `index.js`: inside `init()`, after `ready = true`, register exactly five subscriptions through `const E = EVENT(ctx)` — `GENERATION_STARTED`, `CHAT_COMPLETION_SETTINGS_READY`, `TEXT_COMPLETION_SETTINGS_READY`, `STREAM_TOKEN_RECEIVED`, `MESSAGE_RECEIVED` — each only when `E[name] !== undefined`, collecting any absent names into a single `console.warn` line prefixed with `LOG_PREFIX`. Keep this as one self-contained block (one import line from `./src/boundary.js`, one loop) so it merges cleanly with brief 0007's separate CHAT_CHANGED subscription; do not refactor `init()`'s existing structure, do not introduce a shared subscription registry, and do not touch the interceptor placeholder.
- `tests/helpers/fake-context.js`: add `updateMessageBlock: vi.fn()` to the default context and one exported message-builder helper (e.g. `makeAssistantMessage({ mes, swipes, swipe_id, extra })` returning a plain object shaped per `#message-shape`). **Do not add or rename any key in `eventTypes`** — `tests/bootstrap.test.js:157` asserts it has exactly 11 keys and that file is not in this brief's allowed set; all five event names this brief needs are already there.
- `tests/boundary.test.js` (new): pure-helper and handler tests, at minimum —
  - `applyStopStrings` on a chat body with no `stop` creates `['<persona>:']`; with an existing `stop: ['a','b']` produces `['<persona>:','a','b']`; calling it twice leaves one copy at index 0; a body already containing the literal at index 2 ends with it at index 0 and length unchanged.
  - `applyStopStrings` with `api: 'text'` performs the same on both `stopping_strings` and `stop`, creating either if absent.
  - `reservedLiteral` returns `'Mara:'` for a context whose `substituteParams` expands `{{user}}` to `Mara`, then `'Nadia:'` after the context's `name1`/`substituteParams` change — proving it is recomputed, not stored; returns `''` for `name1: ''` with an identity `substituteParams`, and every handler no-ops with an empty literal (no `stopGeneration`, no `saveChat`, no `stop` field created).
  - `findBoundary` returns `-1` for `'He turned. Mara: left.'` inside a block and for a quoted mention `'"Mara: stop," he said.'`, and returns the block-start index for `'He waits.\n\nMara: steps in.'`; `endsAtLiteral` is `true` for text ending `'\n\nMara:'` and `false` when body text follows.
  - `trimAtBoundary` keeps everything before the delimiter and drops trailing whitespace: `'He waits.\n\nMara: steps in.'` → `'He waits.'`.
  - `onStreamToken` calls `ctx.stopGeneration()` once across several cumulative chunks that all contain the literal, and again after `onGenerationStarted` resets the flag; never calls it when the literal appears only mid-line; never calls it for `type: 'quiet'` or `'impersonate'`.
  - `onMessageReceived` trims `mes` and `swipes[swipe_id]`, sets `extra[METADATA_KEY].boundary === true`, and calls `updateMessageBlock` and `saveChat` once each; leaves a user message (`is_user: true`) untouched with no save; leaves a message without the literal untouched with no save and no re-render; a message that is only `'Mara: '` trims to `''` and stays in `chat[]` with `chat.length` unchanged.
  - `updateMessageBlock` is called with `(index, message)` where `message` is the same object that was mutated — assert identity, since the renderer reads the object it is handed (`#updatemessageblock`).

## Out of scope (explicit)
- Any setting, toggle, UI control, persisted stop-string list, or configurable character name. The literal is derived from the live persona on every request, full stop.
- Rolling back an incomplete trailing block, classifying natural completion vs max-output, or any other §14 outcome beyond the two named above. `truncateToLastCompleteBlock` / `isTrailingBlockComplete` must not be called from this module; that is `recovery`'s brief (INV-8, `docs/protocol/host-mapping.md#s14-recovery`).
- Writing anything into `chatMetadata`, reading canonical state, or importing anything brief 0007 adds. Boundary works on the request body and the received message only.
- Capturing, transforming, or prompting for the collaborator's block after the stop (§9/§10 = `capture`), and any barge-in trigger, button, or affordance (§15 is satisfied here by *not* gating: the module makes no claim that a stop is required before the collaborator may write).
- Escaping, rewriting, or lint-flagging occurrences of the literal inside manuscript prose. PLAN §8's "ordinary content must not contain the literal" is prompt-level (`docs/protocol/invariants.md#enforcement-model`); the only code-side consequence is that a block-start occurrence is treated as the boundary.
- Touching `GENERATION_ENDED`/`GENERATION_STOPPED` for pairing or bookkeeping (`#generation-stopped`: never count on pairing).
- Adding `updateMessageBlock` (or anything else) to `REQUIRED_KEYS`, which would change the capability gate and `tests/bootstrap.test.js`. The handler calls it directly off the fresh context.
- Passing the `{ rerenderMessage }` option, detecting whether the message is streaming, reading `ctx.streamingProcessor`, calling `addOneMessage`, or any other DOM or render work beyond the single `updateMessageBlock(index, message)` call.
- A second stop literal, a `\n\n`-prefixed variant, or any regex-based stop. §8 rejects the whitespace-prefixed form explicitly.
- Deduping or reordering stop strings ST itself put in the array beyond removing exact duplicates of our own literal.
