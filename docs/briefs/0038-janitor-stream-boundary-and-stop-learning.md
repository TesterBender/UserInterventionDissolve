## Goal
The Janitor script enforces INV-2 on the response as well as the request. The fetch response wrapper the shell already installs (`docs/modules/janitor-transport.md#response-wrapper`) parses OpenAI chat-completions SSE frames, accumulates the delta text, and forwards upstream frames unchanged until the bare reserved literal appears at a block start; at that point it forwards the text before the literal, cancels upstream, and synthesises the terminal frames Janitor's parser needs (`finish_reason: "stop"` and `data: [DONE]`). When the provider honoured the `stop` parameter the literal never arrives and the rewriter is a pass-through whose forwarded bytes equal the upstream bytes exactly. When a provider answers a request that carried `stop` with a 4xx whose body names the parameter — the reasoning routes — the route is recorded as stop-rejecting in the script's own storage, TTL-free and per `host+path+model`, and every later request on that route omits `stop` and relies on the stream cut. Whenever the response side has positive evidence that a generation ended at the boundary, it writes brief 0037's `pendingBoundaryAfter` marker; on any other completion it clears it, so the marker always describes the most recent generation. Nothing under `src/` changes; the bundle is rebuilt and committed.

## In scope

**`janitor/sse.js`** (new; pure over chunks, no `fetch`, no storage, no `window` beyond `TextDecoder`/`TextEncoder`):
- `createBoundaryFilter(literal)` → an object with `push(chunk: Uint8Array) → Uint8Array[]`, `flush() → Uint8Array[]`, and the read-only fields `done` (the boundary fired and upstream may be cancelled), `boundaryHit`, and `completionText()` (the accumulated delta text actually forwarded).
- Framing: buffer decoded text, split on the SSE record separator (a blank line), and process only **complete** records; an incomplete trailing record stays in the buffer. A record that is not `data:`-prefixed, or whose payload is `[DONE]`, or whose JSON does not parse, is forwarded verbatim and contributes no text — the filter never rewrites what it does not understand.
- Delta accumulation: `choices[0].delta.content` when it is a string; anything else contributes nothing.
- Boundary test: after each record, `findBoundary(accumulated, literal)` (`src/boundary.js`) — the bare literal at a **block start** and nothing else (`docs/modules/boundary.md#block-start-only`). An empty `literal` disables the filter entirely: every chunk is forwarded verbatim and `boundaryHit` stays false.
- **Deferred release.** A record whose accumulated text ends in a non-empty proper prefix of the literal is held rather than forwarded, and released verbatim, in order, as soon as a later record proves the match fails or `flush()` runs. This bounds the hold-back by the literal's length — it is not the one-block hold-back the plan refuses — and it is what stops a partial persona name (`Mar`) from reaching Janitor's saved message when the literal is split across frames.
- On a hit: forward the held records whose contribution ends at or before the cut; for the record that spans the cut, emit **one** synthesised `data:` frame carrying the text before the cut as `choices[0].delta.content`, omitted when that text is empty; then emit a synthesised frame with `choices[0] = {index: 0, delta: {}, finish_reason: 'stop'}` and `data: [DONE]`. Synthesised frames copy `id`, `object`, `created` and `model` from the last parsed upstream frame, and carry no field upstream did not send. Set `done`; every later `push` returns `[]`.
- `JANITOR_PARTIAL_LITERAL_HOLD` or any other tunable is **not** introduced: the hold length is `literal.length - 1`, derived, not configured.

**`janitor/stop-routes.js`** (new):
- `stopRouteKey(url, model)` → `` `${host}${path}|${model}` `` from a parsed URL, `''` when the URL does not parse.
- `isStopRejected(key, storage = localStorage)` and `recordStopRejected(key, storage = localStorage)` over one `localStorage` entry holding a JSON array of keys. **TTL-free**, never expired, never cleared by the script; a read failure or unparsable value is treated as "nothing learned" and a write failure warns once, like `saveJanitorState` (`docs/modules/janitor-adapter.md#stored-state`).
- The entry is keyed by the new constant below and is deliberately *not* per chat: a route's refusal is a property of the provider, not of a conversation.

**`janitor/constants.js`** — one addition: `JANITOR_STOP_ROUTES_KEY = 'uid-janitor-stop-rejected-v1'`, a key distinct from `STORAGE_KEY_PREFIX + <chatId>` so it can never collide with a chat entry.

**`janitor/shell.js`** — the seam widens and the response is handled per plan:
- **Transform seam contract.** `transform(data, context)` now returns a falsy value for pass-through, or a **plan object** `{ modified, literal, stopSent, routeKey, onCompletion }`. The shell re-serialises when `plan.modified` is truthy (brief 0028's rule, unchanged), wraps the response with the boundary filter when `plan.literal` is a non-empty string, and otherwise wraps exactly as today. A boolean return is no longer part of the contract; the phase-2 and phase-3 tests that return `true` are updated to return `{ modified: true }`. `docs/modules/janitor-transport.md#transform-seam` states the new shape.
- **Error branch.** When the dispatched response has `status >= 400 && status < 500` and `plan.stopSent` is true and `plan.routeKey` is non-empty, read `response.clone().text()` in a `try`, and when the body matches the stop-parameter pattern (one module-level regexp, `/\bstop(?:_sequences)?\b/i`), call `recordStopRejected(plan.routeKey)` and `console.warn` once per key. The response itself is returned untouched — no retry, no resend, no body rewrite. A clone failure is swallowed.
- **Rewriting branch.** The existing fresh `ReadableStream` gains the filter: each upstream chunk goes through `push` and its results are enqueued; when `done` becomes true, cancel the upstream reader and close the controller; on upstream end, enqueue `flush()` results and close. `cancel` still cancels upstream. Status, headers and the copied `url`/`redirected`/`type` are unchanged.
- **Non-streaming JSON.** When the response's `content-type` is JSON rather than `text/event-stream` and a `plan.literal` exists, read the whole body text once, and if it parses and `choices[0].message.content` is a string containing a block-start boundary, replace that field with `trimAtBoundary(text, literal)` and return a `Response` built from the re-serialised JSON with the original status, headers and metadata; anything that does not parse or does not match is returned unchanged. This is the cheap half of the open ledger item "the stream can be non-streaming JSON when Janitor's streaming toggle is off"; no other dialect and no Anthropic event stream is handled.
- **Completion callback.** After the response body finishes (normal end, boundary cut, or JSON branch), call `plan.onCompletion({ boundaryHit, text })` exactly once, in a `try`, where `text` is the forwarded completion text. It is not called for a pass-through response or an error response.

**`janitor/transform.js`** — three changes, no re-ordering of brief 0033/0037 steps:
- **Step 12, stop.** Compute `routeKey = stopRouteKey(context.url, context.adapter.modelName)`; when `isStopRejected(routeKey)`, skip `applyStopStrings` entirely and record `stopSent = false`; otherwise apply it as today and record `stopSent = true`. One `console.info` field (below) says which happened. No retry logic and no un-learning.
- **Return value.** Return the plan object instead of `true`: `{ modified: true, literal, stopSent, routeKey, onCompletion }`. The gated pass-through paths keep returning `false`.
- **`onCompletion`.** A closure over `context.chatId` and the `messageId` of the **last** aligned, sentinel-dropped history entry of this request (`''` when it has none). It reloads state with `loadJanitorState` (another tab may have written since dispatch), sets `pendingBoundaryAfter` to that id when the completion is a boundary and the id is non-empty, sets it to `''` otherwise, and saves when the value changed. It writes nothing else — `boundaries[]` is resolved at the next derivation by brief 0037 and never here.
- **Boundary evidence (pinned rule).** A completion is a boundary when either (a) the filter reported `boundaryHit`, or (b) `stopSent` was true and the forwarded text is empty or ends with a block delimiter — the shape a completion has when the provider itself cut immediately before a block-start literal (`docs/api/janitor.md#empty-completion-is-stored-as-an-empty-message`, PLAN §14). Every other completion clears the marker. A false positive costs nothing (a complete generation exempted from a rollback that would not have changed it); a false negative costs one rollback of a deliberate stop, which brief 0037 already records as its residual cost.
- **Report.** The `console.info` line gains one field, `stop <sent|skipped>`. It stays one line.

**Tests — `tests/janitor/`** (recorded fixtures under `tests/janitor/fixtures/`, as JSON-string SSE transcripts):
- **pass-through is byte-identical**: for a recorded SSE transcript containing no literal, the concatenation of the bytes the caller reads through the wrapper equals the concatenation of the upstream chunks, for a transcript delivered in one chunk, in per-frame chunks, and in chunks split mid-frame;
- **suppression**: a transcript whose deltas spell prose then `\n\nMara:` yields forwarded text ending exactly at the prose (no literal, no trailing delimiter debris beyond what upstream sent before the cut), a final frame with `finish_reason: 'stop'`, a trailing `data: [DONE]`, and a cancelled upstream reader;
- **split literal**: the same literal split across three frames is never forwarded in part;
- **not a boundary**: a mid-paragraph `Mara:` inside a delta is forwarded untouched and sets no boundary;
- **empty literal**: the filter forwards everything verbatim;
- **boundary → pending**: a suppressed generation writes `pendingBoundaryAfter` equal to the last aligned entry's `messageId`, and the next transform over a body carrying the saved assistant message resolves it into `boundaries[]` (the joint 0037/0038 path);
- **non-boundary clears**: an ordinary completion clears a stale marker;
- **stop learning**: a 4xx whose body names `stop` after a request that sent `stop` records the route; the next request on that route dispatches a body with no `stop` field written by us, while a request on a different host, path or model still writes the literal first; a 4xx whose body does not name the parameter records nothing; a 500 records nothing;
- **three-turn prefix across a boundary stop**: a boundary-suppressed turn followed by two further turns still produces a byte-identical `[final, control]` prefix;
- **non-streaming JSON**: a JSON completion whose content carries a block-start literal is delivered trimmed; one without is delivered byte-identically.

**`dist/janitor-manuscript-dissolve.user.js`** — regenerated with `npm run build:janitor` and committed. Never hand-edited.

### Decisions this brief takes (do not re-open during implementation)
- **Cancel upstream and synthesise the terminal frames is the primary path**; letting upstream run to completion while forwarding nothing after the cut is the **recorded fallback** and is not implemented. The ledger item "early stream close is a failure to Janitor's parser unless terminal frames arrive" is open, which is exactly why the terminal frames are synthesised rather than the stream simply closed; if a capture later shows Janitor's parser rejecting the synthesised frames, the fallback is adopted by amendment to this brief and costs wasted tokens only. This is a decision, not a toggle: no setting, no constant with two live values, no runtime detection.
- **Learning is one-way and TTL-free.** A route that rejected `stop` stays learned for the life of the browser profile. No expiry, no retry-to-unlearn, no UI to clear it.
- **No retry of the rejected request.** The 4xx is returned to Janitor as-is; the human sees the provider's own error and sends again.
- **Only the OpenAI chat-completions SSE dialect and its plain-JSON sibling are handled.** Anthropic events remain pass-through.
