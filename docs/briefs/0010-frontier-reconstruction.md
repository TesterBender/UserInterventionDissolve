# Brief 0010 — `frontier`: total reconstruction of model-visible history in the interceptor
Status: draft
Complexity: high
PLAN sections: §11 (the live cycle — canonical history → continuation control → generation → boundary → collaborator block → *frontier normalised* → new continuation control; the variation in how often the collaborator intervenes must remain invisible as transport structure), §12 (the mutable frontier must not accumulate one visible continuation seam per intervention: the next request reconstructs the still-mutable manuscript as one assistant span plus exactly one continuation-control turn; "normalisation happens every request, freezing happens only when the frontier reaches its transport target"), §13 (the continuation-control turn is a neutral, non-evaluative host constant, byte-identical in frozen history for stable conditioning and prefix caching), §24 (the abstract transformation: what survives is prose, causality and who did what in the fiction; what is discarded is who typed which block, how many requests occurred, where stops fired, how often the collaborator intervened)
Invariants touched: INV-4 (this module is its owner — reconstruction happens on every request, not at freeze time), INV-5 (exactly one continuation-control seam, at the active edge, byte-identical), INV-10 (many live histories, one model-visible manuscript — the reconstruction is a pure function of canonical state)

## Goal
`src/frontier.js` exists and turns canonical state into the model-visible history. On every non-dryRun generation that is not `quiet`/`impersonate`, the `generate_interceptor` global replaces the per-request chat array in place with: one assistant message per frozen span, one assistant message for the mutable frontier (only when it is non-blank), and one user message carrying `CONTINUATION_CONTROL`. Nothing outside that array is touched — character card, persona, world info, examples and system blocks are untouched because the interceptor only ever sees `coreChat`. The visible `chat[]` is never read, rewritten, hidden or deleted by this module: the collaborator's own messages, the `captured` marks of brief 0009 and the boundary trims of brief 0008 stay in the log, and none of them is an input to reconstruction. The output array is a pure function of `{frozen, frontier}` and the two names, containing nothing time-varying, so two chats with byte-identical canonical state and completely different live histories produce byte-identical arrays.

## In scope
- **`src/frontier.js`** (new). Imports: `getCtx` from `src/host.js`, `METADATA_KEY` from `src/constants.js`, `CONTINUATION_CONTROL` from `src/prompt.js`, `getState` from `src/state.js` — all import-only, none of those files is edited. The module must not contain the identifier `SillyTavern` (`docs/modules/host.md#single-door`; `tests/bootstrap.test.js` asserts this). Exports exactly four names:
  - `buildHistory(state, { name1, name2 })` → array of ST-shaped messages. Pure: no host access, no module state, no clock, no randomness.
    - Returns `[]` when `state` is not an object, when `state.frozen` is not an array and `state.frontier` is not a non-blank string — i.e. when there is nothing canonical to say. See the empty-state rule below.
    - For each element of `state.frozen` in array order whose `.text` is a non-empty string after `String(...)`: push `{ name: assistantName, is_user: false, is_system: false, mes: span.text, extra: { [METADATA_KEY]: { reconstructed: true } } }`. `span.words` and `span.createdAt` are **not** read; they never reach the model.
    - Then, only when `String(state.frontier ?? '').trim() !== ''`, push the same assistant shape with `mes: state.frontier` (the frontier is passed through verbatim, not trimmed, not re-joined, not re-wrapped — `state.js` owns its block joining).
    - Then always push `{ name: userName, is_user: true, is_system: false, mes: CONTINUATION_CONTROL, extra: { [METADATA_KEY]: { reconstructed: true } } }` — provided the array is not otherwise empty (see below).
    - `assistantName = String(name2 ?? '')`, `userName = String(name1 ?? '')`. An empty persona name is legal (`docs/modules/bootstrap.md#capability-gate`) and must not be substituted with a placeholder.
    - **No time-varying or per-request field may appear on any produced message**: no `send_date`, no `gen_started`/`gen_finished`, no `swipes`/`swipe_id`, no token counts, no index, no id. This is what makes INV-10 testable by byte comparison and what gives frozen turns the byte-identity INV-5 and the §23 prefix-caching row ask for. The five fields above are the whole message (`docs/api/sillytavern.md#message-shape`).
    - **Empty-state rule.** If there are no usable frozen spans *and* the frontier is blank, return `[]` — not a lone continuation-control turn. A blank canonical state means there is nothing to continue from, and emptying the request chat to a single "continue" instruction would erase a real chat's history from the model's view. `state.js` materialises the frontier from the open chat on first read (`docs/modules/state.md#initialise-from-chat`), so in practice this case is a genuinely empty chat, where leaving the request array alone is indistinguishable from replacing it.
  - `applyToRequestChat(chat, history)` → `boolean` (`true` when it replaced anything). Mutates in place and nothing else: return `false` when `chat` is not an array or `history` is not a non-empty array; otherwise `chat.length = 0` then `for (const message of history) chat.push(message)` — a loop, not `push(...history)`, so a long frozen list cannot hit the argument-count limit. Never reassigns `chat`; the caller's array identity is what ST reads back (`docs/api/sillytavern.md#generate-interceptor`).
  - `shouldReconstruct(type)` → `boolean`. `false` for `'quiet'` and `'impersonate'`, `true` for every other value **including `undefined` and unknown strings**. Same rule and same reasoning as `docs/briefs/0008-boundary-module.md` ("Generation-type rule"): a `quiet` generation is out-of-band and its output never becomes a manuscript block, and an `impersonate` generation is ST writing the collaborator's own turn — replacing history for either would corrupt an operation the protocol has no stake in. Types per `docs/api/sillytavern.md#generation-types`.
  - `interceptGeneration(chat, contextSize, abort, type, ctx = getCtx())` → `Promise<boolean>`. The whole interceptor body lives here, not in `index.js`. Defaulted-`ctx` parameter form per `docs/decisions/0002-structure-from-intercede.md` ("Injectable host"); never cache `ctx` (`docs/api/sillytavern.md#getcontext`). Steps:
    1. Return `false` when `shouldReconstruct(type)` is false.
    2. `const history = buildHistory(getState(ctx), { name1: ctx.name1, name2: ctx.name2 })`.
    3. Return `applyToRequestChat(chat, history)`.
    - `contextSize` is accepted and ignored: no trimming, no budget arithmetic, no dropping of frozen spans to fit. `abort` is accepted and **never called** — this module has no failure mode that should cancel a generation.
    - It writes nothing: no `saveMetadata`, no `saveChat`, no mutation of canonical state. `getState` may lazily materialise state on first read; that is `state`'s documented behaviour and this module adds no persistence of its own.
- **`index.js`** — one change only: the `generate_interceptor` global's body becomes `return interceptGeneration(chat, contextSize, abort, type);` with one added import from `./src/frontier.js`, and the placeholder's pointer comment is repointed to `docs/modules/frontier.md#interceptor-body`. Keep the global's name and arity exactly as they are (`INTERCEPTOR_GLOBAL` must keep matching `manifest.json`, which is not edited). Do not add any event subscription, do not touch brief 0007's `CHAT_CHANGED` subscription or briefs 0008/0009's subscriptions, do not refactor `init()`, and do not make the interceptor depend on `ready`.
- **`docs/modules/bootstrap.md`** — rewrite the body under the existing `## Interceptor placeholder` heading, **keeping the anchor `{#interceptor-placeholder}` intact** (`src/constants.js:16` points at it and that file is not editable here), so it says the global now delegates one call to `src/frontier.js` and holds no logic. That is the single allowed heading edit in this file.

## Out of scope (explicit)
- **Anything in `CHAT_COMPLETION_PROMPT_READY`, `GENERATE_AFTER_COMBINE_PROMPTS` or `GENERATE_BEFORE_COMBINE_PROMPTS`.** dryRun token-count parity is brief 0011 and is blocked on verification; `src/frontier.js` must contain none of those event names and `index.js` must gain no subscription here. A `toPromptManagerEntries`-style export belongs to 0011, not to this brief.
- Reading, rewriting, hiding, deleting, re-rendering or reordering the visible `chat[]`. `ctx.chat` is not read by this module at all (`getState` reads it only on first materialisation, inside `state.js`). No `updateMessageBlock`, `deleteMessage`, `addOneMessage`, DOM or CSS work.
- Reading any per-message marker as an input: `extra[METADATA_KEY].captured` (brief 0009) and `.boundary` (brief 0008) are never consulted. Reconstruction reads state and only state — that is what makes INV-10 hold rather than merely hold in practice.
- Freezing, word counting, cut selection, calling `pushFrozen`, or any transport-target logic (§16/§17 — the `freeze` brief). This brief never moves text from frontier to frozen and never mutates `state`.
- Outcome classification, rollback of incomplete trailing blocks, `truncateToLastCompleteBlock`/`isTrailingBlockComplete` (§14/INV-8 — `recovery`).
- Injecting, moving or suppressing the system prompt, character card, persona, world info, dialogue examples or any prompt-manager block; `setExtensionPrompt` is not called. The interceptor only ever receives `coreChat` (`docs/api/sillytavern.md#generate-interceptor`), so "the card is untouched" is structural here, not a promise this brief has to keep by hand. Whether to suppress example messages is left open for 0011/`freeze`; it is not decided here.
- Calling `abort()`, aborting on empty state, warning the user, or any generation control. Also no reading of `contextSize`, no context-budget trimming, no summarisation, no dropping of old frozen spans.
- Any setting, toggle, threshold, per-chat option, `extensionSettings` read/write, or a configurable continuation string. `CONTINUATION_CONTROL` is a single constant imported from `src/prompt.js` and is used byte-for-byte, including on the live edge (PLAN §13 permits a live-edge variant only if a brief justifies one; this brief does not, and INV-5's byte-identity is the reason).
- Adding `name2` (or anything else) to `REQUIRED_KEYS`, which would change the capability gate and `tests/bootstrap.test.js`. `name2` is read off the fresh context with an empty-string fallback.
- Detecting or special-casing the chat-completion `send_if_empty` quirk (`docs/api/sillytavern.md#empty-send`). A synthetic user message injected by a preset is simply discarded with everything else when the array is cleared; no code may look for it.
- Group chats (`docs/api/sillytavern.md#group-chats` is unverified), `generateRaw`/`generateQuietPrompt` paths, and any new dependency.
