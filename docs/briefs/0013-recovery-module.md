# Brief 0013 — `recovery`: outcome classification, rollback, and the frontier/freeze hook-up
Status: implemented
Complexity: high
PLAN sections: §11 (the live cycle: model generation → boundary → collaborator block → merged into the manuscript → frontier normalised → new continuation; this brief owns the "model generation → merged into the manuscript" leg, the only place model text enters canonical state), §14 (the four generation outcomes: external-character boundary hands the floor to the collaborator; empty output at the boundary leaves the floor with the collaborator and must not be papered over with forced text; natural completion simply continues; maximum-output or exceptional termination rolls the incomplete trailing block back to the last complete boundary and must never freeze a syntactically incomplete block — "exceptional stop artifacts must not become fictional events"), §16 first paragraph (the mutable frontier is periodically promoted into immutable history; freezing is append-only and old spans are not re-cut), §18 (three independent horizons: the generation horizon — how long one generation ran — must not be conflated with the transport horizon; this module calls freeze after every append and lets `freeze` decide by word count alone, never by "one generation = one chunk")
Invariants touched: INV-8 (this module is its owner: abnormal termination rolls back to the last complete block), INV-6 (respected, not owned: frozen spans are never edited — the swipe-replacement rule refuses to touch text that has already been frozen), INV-4 (the frontier is written here but never reconstructed here)

## Prerequisites
`src/recovery.js` imports from `src/boundary.js` (brief 0008), `src/freeze.js` (brief 0011) and `src/state.js` (brief 0007, already in the tree). If `src/boundary.js` or `src/freeze.js` does not yet exist when this brief is picked up, **stop and report** — do not stub, re-implement, or inline any part of them.

## Goal
`src/recovery.js` exists and is the single place where model-generated text enters canonical state. On every received assistant message of an eligible type it classifies the text into one of PLAN §14's four outcomes, rolls an incomplete trailing block back to the last complete block boundary (INV-8), appends the resulting text to the mutable frontier exactly once, marks the message so it can never be appended twice, asks `freeze` whether a span may now be promoted, and persists. The classification is purely textual because SillyTavern exposes no finish reason (`docs/api/sillytavern.md#finish-reason`, status: absent) — there is no other signal and the module must not pretend there is. A generation that fails, is aborted, or never produces a message changes nothing at all, so INV-8 holds for abnormal termination by construction. `index.js` gains one import and one guarded MESSAGE_RECEIVED subscription, registered **after** `boundary`'s block so `boundary` trims first.

## In scope

### `src/recovery.js` — new module
Imports: `getCtx` from `./host.js`; `METADATA_KEY`, `LOG_PREFIX` from `./constants.js`; `isTrailingBlockComplete`, `truncateToLastCompleteBlock` from `./grammar.js`; `getState`, `appendToFrontier`, `setFrontier`, `save` from `./state.js`; `reservedLiteral`, `findBoundary` from `./boundary.js`; `maybeFreeze` from `./freeze.js`. Every one of those files is **import-only**. The module must not contain the identifier `SillyTavern` (`docs/modules/host.md#single-door`; `tests/bootstrap.test.js` asserts it appears nowhere outside `src/host.js`).

**Module state**, for the resample fallback only: `lastAppend` (`{ index, text } | null`). Exported `resetRecoveryState()` exists for tests. No other module-level mutable state; the context is never cached (`docs/api/sillytavern.md#getcontext`).

**Export 1 — `classifyOutcome(text, literal, boundaryMarked = false)` → `'empty' | 'boundary' | 'complete' | 'incomplete'`.** Pure: no host, no state, no I/O. Decided in exactly this order:

1. `const trimmed = String(text ?? '').trim()`. If `trimmed === ''` ⇒ `'empty'`. **This precedence is deliberate and must not be reordered:** a message that `boundary` trimmed down to nothing is PLAN §14's *"Empty output at the boundary"* — the model tried to place the external character immediately — and its action (append nothing, freeze nothing) is the same whether or not the marker is set. Testing emptiness first makes the table total and unambiguous.
2. If `boundaryMarked === true` ⇒ `'boundary'`. The flag is `message.extra[METADATA_KEY].boundary`, written by `boundary`'s own MESSAGE_RECEIVED handler (`docs/briefs/0008-boundary-module.md`); by the time recovery runs, the literal has already been trimmed out of the text, so the marker — not the text — is the reliable signal.
3. Else if `literal` is a non-empty string and `findBoundary(text, literal).endsAtLiteral === true` ⇒ `'boundary'`. Textual fallback for the case where `boundary`'s trim did not run (event not registered, empty persona name, unusual backend). Recovery does **not** trim here; see Out of scope.
4. Else if `isTrailingBlockComplete(text)` ⇒ `'complete'` (PLAN §14 "Natural completion": transport behaviour, not scene closure — nothing special happens).
5. Else ⇒ `'incomplete'` (PLAN §14 "Maximum-output termination" and "Safety, recitation, provider interruption" collapse to the same textual signature and the same default rule).

A `'boundary'` outcome is **never** rolled back even when its trailing block lacks terminal punctuation: the model handed the floor over deliberately at a block boundary, and discarding the block before the handoff would delete text the model meant to keep. Record this as a decision in the module doc.

**Export 2 — `onMessageReceived(index, type, ctx = getCtx())` → `Promise<'skipped' | 'empty' | 'boundary' | 'complete' | 'incomplete'>`.** Defaulted-`ctx` parameter form per `docs/decisions/0002-structure-from-intercede.md` ("Injectable host"). Steps, in order:

1. **Eligibility**, identical to `boundary`'s receipt-side rule so the two handlers never disagree: return `'skipped'` when `type` is `'quiet'`, `'impersonate'` or `'first_message'`. Unknown and `undefined` types are processed (`docs/api/sillytavern.md#message-received`: do not discard unknown types; `#generation-types` for the value set). Do not import the rule from `boundary`; restate it, and state in the doc that the two lists are intentionally duplicated because the modules are wired independently.
2. `const message = ctx.chat?.[index]` — return `'skipped'` unless it is a non-null object, unless `typeof message.mes === 'string'`, and unless `message.is_user !== true && message.is_system !== true` (`docs/api/sillytavern.md#message-shape`).
3. `const mark = message.extra?.[METADATA_KEY] ?? {}`; `const isResample = type === 'swipe' || type === 'regenerate'`. **Idempotence guard:** return `'skipped'` when `mark.appended === true && !isResample`. This is the whole defence against double-appending — the module subscribes to nothing else, so a repeated MESSAGE_RECEIVED for the same index is the only replay path it can see.
4. `const literal = reservedLiteral(ctx)` (may be `''`; everything below tolerates that). `const outcome = classifyOutcome(message.mes, literal, mark.boundary === true)`.
5. `let text = message.mes; let chatDirty = false;`
   **Rollback (INV-8), only when `outcome === 'incomplete'`:** `text = truncateToLastCompleteBlock(message.mes)`; `message.mes = text`; if `Array.isArray(message.swipes) && message.swipes[message.swipe_id] !== undefined`, assign the same string to `message.swipes[message.swipe_id]` (`#message-shape`); `ctx.updateMessageBlock(index, message)` — called with exactly two arguments, passing the mutated object itself, because the renderer reads the object it is handed (`#updatemessageblock`); `chatDirty = true`. If nothing complete remains, `text` is `''` and the message stays in `chat[]` with empty content — **it is not deleted, no placeholder is substituted, and no regeneration is triggered** (PLAN §14: the artefact must not become a fictional event, and §14's empty-output rule forbids forcing text).
   One `updateMessageBlock` call, in this branch only: it is the only branch that edits message text. It is correct on both receipt paths — a silent no-op before `addOneMessage` on the non-streaming path, and the only thing that repaints an already-painted streamed message (`#edit-on-receipt`).
6. If `outcome === 'empty'`, or if the rollback left `text.trim() === ''`: append nothing, call no freeze, write no marker to canonical state; `if (chatDirty) await ctx.saveChat()`; return the outcome. **The floor stays with the collaborator** (PLAN §14).
7. **Append.** `const state = getState(ctx); const appendedText = text.trim();`
   a. **Resample replacement**, only when `isResample`: let `previous = typeof mark.appendedText === 'string' && mark.appendedText !== '' ? mark.appendedText : (lastAppend?.text ?? '')`. When `previous !== ''`:
      - If `state.frontier.replace(/\s+$/, '').endsWith(previous)` ⇒ `setFrontier(state, state.frontier.replace(/\s+$/, '').slice(0, -previous.length).replace(/\s+$/, ''))`. The trailing occurrence — and only the trailing occurrence — is removed, so the new swipe replaces the old text instead of accumulating beside it.
      - Otherwise a freeze has already carried that text into an immutable span, or the collaborator has written past it. **Leave the frontier untouched and append anyway**, emitting one `console.warn` line prefixed with `LOG_PREFIX` saying the previous text could not be replaced because it is no longer at the frontier edge. INV-6: frozen spans are append-only and are never edited, not even to undo a swipe.
      - The `lastAppend` fallback exists because the marker may be absent when the host replaces rather than edits the message on a resample path. It depends on no unverified ST behaviour: when neither source yields a previous string, the branch simply does nothing.
   b. `appendToFrontier(state, text)` — the state helper trims and joins with `BLOCK_DELIMITER`, which is why `appendedText` is recorded as `text.trim()`: that is byte-exactly what landed in the frontier, so the `endsWith` test above is exact.
   c. `lastAppend = { index, text: appendedText }`.
   d. **Marker:** `message.extra = message.extra ?? {}`; `message.extra[METADATA_KEY] = { ...(message.extra[METADATA_KEY] ?? {}), appended: true, appendedText }`. The spread preserves sibling flags owned by other modules in the same namespace (`boundary` writes `boundary`, `capture` writes `captured`). `chatDirty = true`.
8. **Freeze.** `maybeFreeze(state, literal, {})` — called on every append and on no other occasion, with no options, ignoring the return value except for an optional single `console.log`/`console.warn`-free path (no logging is required). `freeze` is pure and never persists; recovery is its caller and the one that persists (`docs/briefs/0011-freeze-module.md`). Recovery makes no decision about *whether* the frontier is long enough — that is `freeze`'s word-count rule alone, which is what keeps the generation horizon and the transport horizon separate (PLAN §18).
9. **Persist.** `await save(ctx)` (metadata: the frontier and any new frozen span) and then `if (chatDirty) await ctx.saveChat()` (the message: rolled-back text and the `appended`/`appendedText` marker). At most one `saveChat()` and at most one `saveMetadata()` per invocation. Return the outcome.

## Out of scope (explicit)
- **Any subscription other than MESSAGE_RECEIVED.** No GENERATION_STOPPED, no GENERATION_ENDED, no MESSAGE_EDITED, no MESSAGE_UPDATED, no MESSAGE_SWIPED, no MESSAGE_DELETED, no STREAM_TOKEN_RECEIVED. Abnormal stops, provider errors and aborted generations need **no code**: the frontier changes only on MESSAGE_RECEIVED, so a generation that dies leaves canonical state byte-identical and INV-8 holds by construction. ENDED/STOPPED cannot be paired with STARTED anyway (`docs/api/sillytavern.md#generation-stopped`).
- **Any edit-sync between `chat[]` and canonical state.** Editing, deleting or browsing back to an older swipe of a message changes the visible log only; the frontier keeps the text that was appended when the message was received. The swipe/regenerate rule in step 7a is the single, minimal exception and exists only because a resample re-fires MESSAGE_RECEIVED for text the module itself appended moments earlier. No general diffing, no re-derivation of the frontier from `chat[]`, no "resync" command.
- **Re-opening frozen spans.** No `unfreeze`, no re-cut, no editing of `state.frozen[*]`, no removal of text that has already been promoted — including when a swipe's previous text landed inside a frozen span (INV-6; that case warns and appends).
- **Trimming at the reserved literal.** `boundary` owns the trim and the `boundary` marker (`docs/briefs/0008-boundary-module.md`); recovery only reads them. `trimAtBoundary` must not be called, and the literal must not be stripped, escaped or re-detected for any purpose beyond the `endsAtLiteral` fallback in `classifyOutcome`.
- **Retry, regeneration, continuation or any automatic follow-up action.** PLAN §14 permits a host to "retry, regenerate, or otherwise recover according to host policy"; this host's policy is to do nothing and leave the next move to the collaborator. No `ctx.generate(...)`, no `/trigger`, no auto-swipe, no toast, no prompt to the user.
- **Exact partial continuation** of an incomplete block (PLAN §14's permitted optimisation). The default rule — roll back — is what is implemented; no `'continue'` generation type is used or detected.
- **Deleting the message** when a rollback empties it, and **substituting placeholder text** for an empty outcome. §14 forbids forcing model text merely to avoid an empty generation.
- **Choosing the cut, counting words, or deciding whether to freeze.** `maybeFreeze` is called unconditionally after every append and answers by itself; recovery passes no options and implements no threshold, no jitter, no word count (`docs/briefs/0011-freeze-module.md`).
- **Frontier reconstruction, the interceptor, prompt-ready parity, the continuation string, capture, the seed span, and pre-freeze lint.** All belong to other briefs; reconstruction reads state only (`docs/briefs/0010-frontier-reconstruction.md`).
- **Any setting, toggle, threshold, UI control, `extensionSettings` read/write, `REQUIRED_KEYS` change, or new dependency.** `updateMessageBlock` is called straight off the fresh context, exactly as `boundary` does, and is not added to `REQUIRED_KEYS`.
- **Group-chat branching** (`docs/api/sillytavern.md#group-chats` is unverified) and any dependence on a finish reason, `streamingProcessor`, `is_send_press`, or any other ST internal not in the API inventory.

- [x] **Classification table.** `classifyOutcome` returns: `'empty'` for `''`, `'   \n '`, `undefined` and a non-string — including when `boundaryMarked` is `true`; `'boundary'` for any non-empty text when `boundaryMarked` is `true`; `'boundary'` for `'He waits.\n\nMara:'` with literal `'Mara:'` and `boundaryMarked` false; `'complete'` for `'He waits.\n\nShe left.'`; `'incomplete'` for `'He waits.\n\nShe turned and'`; `'complete'`/`'incomplete'` unchanged when `literal` is `''`.
