# Brief 0042 — Janitor context override: per-chat store, request application, drift capture, transfer
Status: draft
Complexity: high  (it adds a second `localStorage` entry and its own format version, changes what the request pipeline's system-message step composes, changes the exported transfer shape, and adds a field to the status snapshot — four modules plus a new one)
PLAN sections: §10 (editorial authority is manuscript-wide inside the mutable frontier and belongs to the human — the assembled context Janitor writes is the one piece of the outgoing body the human otherwise cannot touch on this host), §23 (the host supplies "merge external text into manuscript-bearing context"; on this host that merge is the first system message, and nothing in Janitor's own UI lets the human see what finally goes into it), §27 (the override is human-facing and its storage carries no transport information; what reaches the model is one system message whose composition order is fixed)
Invariants touched: INV-10 (nothing about the override, its storage entry or its drift state may reach the model-visible history — it may only change the content of the one system message, which is not history)

Depends on: briefs 0033 (the request pipeline and `foldedSystemMessage`), 0036 (`JANITOR_STATE_FORMAT`, the no-migration storage rule), 0039 (`janitor/status.js`, `janitor/portable.js`) and 0040 (the panel that will render this). All are merged. **Brief 0043 depends on this one** and must not be started first: 0043 is the panel surface and adds no logic.

Scope source: the orchestrator's 2026-09-14 decision with the user, which ports the optimizer's system-context editor and redesigns it so it never asks at send time. Read from `TamperContainment/TamperMonkeyJanAI.txt`: the **bundle editor model** at L4469–4578 (the whole first system message is one editable unit; the optimizer's own split/seam mode degrades to it — L4482–4511 — which is why the seam is not ported at all) and **per-conversation persistence** at L2663–2778 (`conversation:<identity>` scope, one `localStorage` entry per scope, a version field, no repair). The optimizer's pain is what this brief exists to remove: it compared the whole assembled system message on every send, Janitor aggregates its injections into that message, so every send looked like a change and re-opened a blocking prompt. Here the editable unit excludes the injections by construction, so there is nothing to compare and nothing to ask.

## Goal
A human can replace Janitor's assembled context for one chat, once, and have every later request use their text without being asked again. The editable unit is Janitor's own first system message as a single blob — not a seam-matched split of it — and it excludes both the manuscript prompt this script prepends and every message the envelope diff classifies as an injection. A saved override lives in its own `localStorage` entry keyed by chat id, replaces the editable unit wholesale on every request until it is cleared, and carries a copy of the captured unit it was saved against so a later change in Janitor's own context can be reported. The outgoing system message is always `[manuscript prompt] + [override, else captured unit] + [folded injections]`, byte-stable across repeated identical requests. The captured unit is published in the request status snapshot so the panel (brief 0043) can show it. Nothing in this brief touches the DOM, the manuscript prompt text, the continuation control, the lead-in, the frontier, the history or the canonical state.

## In scope

**`janitor/constants.js`** — two added constants and nothing else:
- `JANITOR_OVERRIDE_KEY_PREFIX = 'uid-janitor-context-v1:'`. It is its own entry, not a field of the stored state, and its prefix deliberately cannot be a `STORAGE_KEY_PREFIX + chatId` key (`uid-janitor-v1:`) nor be matched by the panel's `startsWith(STORAGE_KEY_PREFIX)` filter.
- `JANITOR_OVERRIDE_FORMAT = 1` — this entry's own version field, checked the way `janitorFormat` is (`docs/modules/janitor-adapter.md#stored-state`).

**`janitor/context-override.js`** (new; `localStorage` only through its own accessors, no DOM, no `src/` host code, no import of `janitor/storage.js`):
- `overrideKey(chatId)` → `JANITOR_OVERRIDE_KEY_PREFIX + chatId`.
- `loadOverride(chatId, storage = localStorage)` → `{ text, capturedText, savedAt }` or `null`. `null` for: an empty or non-string chat id, a missing entry, a value that does not parse, a value whose `janitorOverrideFormat` is not `JANITOR_OVERRIDE_FORMAT`, a non-string `text`, or a `text` that is empty after `trim()`. **No migration and no repair**, matching `loadJanitorState`: a foreign value is refused whole with one `console.warn`, never guessed at. A missing entry is not a warning.
- `saveOverride(chatId, text, capturedText, storage = localStorage)` → writes `{ janitorOverrideFormat, text, capturedText, savedAt: Date.now() }`. When `text.trim()` is empty it **removes** the entry instead of writing one: an empty override is not an override, and the human's way to say "go back to Janitor's text" is Clear, which is the same act. A write that throws is caught and warned and never raised at the caller, for the reason `saveJanitorState` gives.
- `clearOverride(chatId, storage = localStorage)` — removes the entry; removing an absent entry is not an error.
- `overrideDrift(override, capturedText)` → `true` when `override` is non-null and `override.capturedText !== capturedText`. Exact string inequality: no trimming, no whitespace folding, no length heuristic. It is **informational only** — nothing in this brief or in 0043 blocks, clears, re-saves or re-prompts on drift.

**`janitor/transform.js`** — the system-message step ([system message](../modules/janitor-adapter.md#system-message)) gains the override and nothing else changes:
- The **captured unit** is exactly what the step reads today: `String(messages[systemIndex].content ?? '')` from the **incoming** array, taken before `adapter.messagesContainer.messages` is reassigned, and `''` when `systemIndex === -1`. It is Janitor's own text and only that: the manuscript prompt is prepended afterwards and the injections are appended afterwards, so neither is ever part of the unit. This is the whole of the "ignore injections" requirement, and it is structural rather than a filter.
- `const override = loadOverride(context.chatId)`; the text handed to `foldedSystemMessage` is `override === null ? captured : override.text`. `foldedSystemMessage`'s own signature, its first-sentence probe and its `BLOCK_DELIMITER` joining are **unchanged** — an override that itself contains the prompt's first sentence suppresses the prepend exactly as Janitor's own text would, and no special case is added for that.
- The captured unit is added to the `setRequestStatus({...})` call as `capturedContext`. Nothing is added to the `console.info` report line.
- No other step moves. The override is read after the state load and is not part of it; no step order changes; the pipeline's numbered steps are unchanged apart from what step 6 composes.

**`janitor/status.js`** — one field added to the module-level snapshot: `capturedContext: ''`. No other change; `getRequestStatus()` already copies the object, and a string field needs no special copying.

**`janitor/portable.js`** — the transfer shape carries the override:
- `exportStateJson(chatId, state, override = null)` adds `override` to the wrapper object, after `state`. The default keeps every existing caller working; brief 0043 passes the real value.
- `importStateJson(text)` returns `{ ok: true, chatId, state, override }` where `override` is the parsed object when it has the right `janitorOverrideFormat` and a string `text`, and **`null` otherwise** — including when the file has no `override` key at all, which is every export written before this brief.
- **A malformed or absent override never refuses the import** and never changes a `reason`: the manuscript is what the file exists to carry, and a state that imports while its override is rejected is strictly better than losing both. The existing three reasons (`unreadable`, `not-a-state`, `wrong-format`) are unchanged and no fourth is added.
- **Import replaces the override wholesale, `null` included.** The caller (brief 0043) clears this chat's override when the imported one is `null`. A file that restores a manuscript but leaves the previous chat's context in place is the merge `docs/modules/janitor-adapter.md#state-transfer` already refuses.

**Tests — `tests/janitor/context-override.test.js`** (new) and additions to `tests/janitor/transform.test.js`, `tests/janitor/portable.test.js`, `tests/janitor/status.test.js` (no DOM, no new dependency, storage faked as a plain object as `tests/janitor/storage.test.js` does):
- **application order**: with an override saved, the outgoing system message is exactly the manuscript prompt, then the override text, then each injection, joined by `BLOCK_DELIMITER`, in input order; with no override, the same with Janitor's captured text in the middle;
- **injections are excluded from the unit**: a fixture whose request carries injections classified by `classifyMessages` produces a `capturedContext` that contains none of their text, and an override saved against that capture does **not** drift when a later request carries different injections (the same fixture with an injection added, removed and reworded, three times, reports no drift);
- **drift detection**: changing Janitor's own first system message between two requests makes `overrideDrift` true and changes nothing about what is sent; `overrideDrift(null, anything)` is false;
- **empty is not an override**: `saveOverride` with `''`, `'   '` and `'\n'` removes the entry, and `loadOverride` then returns `null`; a request after it carries the captured unit again (this is the Clear path and the empty path arriving at the same place);
- **Clear restores the captured unit**: transform with an override, `clearOverride`, transform again — the second body's system message is byte-identical to the one the same fixture produces with no override ever saved;
- **byte stability**: three consecutive `transformRequest` calls over the same fixture with an override produce three `===` system message contents;
- **storage refusals**: a non-JSON value, a wrong `janitorOverrideFormat`, a non-string `text` and a missing entry each yield `null`; a throwing `setItem` warns and does not throw;
- **export/import round trip including the override**: `importStateJson(exportStateJson(id, state, override))` returns a deep-equal state **and** a deep-equal override; an export written without the third argument imports with `override: null`; a file whose `override` is a string, a number or an object with the wrong format imports the state successfully with `override: null`;
- **status**: the snapshot after a transformed request carries the captured unit in `capturedContext`, and `getRequestStatus()` cannot be mutated into the module's copy;
- **isolation holds**: no file added or changed by this brief references `document`, `window` or `SillyTavern`.

**`dist/janitor-manuscript-dissolve.user.js`** — regenerated with `npm run build:janitor` and committed. Never hand-edited. New top-level names must not collide with an existing module's (`docs/modules/janitor-build.md#supported-module-syntax`).

### Decisions this brief takes (do not re-open during implementation)
- **The editable unit is the whole first system message (bundle), not a split.** The optimizer's seam matcher exists to separate the human's custom prompt from Janitor's hidden context, and the optimizer itself degrades to the bundle whenever the seam does not match or no envelope baseline is available (L4482–4538). A matcher that silently falls back is a matcher that cannot be relied on, and on this host a mis-split would either edit Janitor's text in place — which `#system-message` forbids — or hide part of the context from the human editing it.
- **Injections are excluded from the unit and from change detection, and this is not a toggle.** It is the whole reason the feature exists, and a toggle would only offer the broken behaviour back.
- **There is no send-time prompt, no grace period, no "send now" and no per-request confirmation.** The editor is opened by the human when they want it, the saved override applies until they change it, and drift is a sentence in the panel.
- **The override is per chat only.** No character scope: the optimizer's character scope needs a stable character id it does not always have and falls back to conversation scope anyway (L2666–2698), and a manuscript is a per-chat object on this host in every other respect.
- **Its own storage entry and its own format version.** Not a field of the stored state, for a decisive reason: a recompile replaces the whole state with `freshState()` (`docs/modules/janitor-adapter.md#recompile`), which would silently delete the human's context text. A separate entry also means a future override-shape bump discards no compiled manuscript, and a `JANITOR_STATE_FORMAT` bump discards no override.
- **The override text is user content.** The script never reads it, parses it, lints it, substitutes macros in it, or rewords it. `docs/decisions/0003-duplication-filter-wording.md` constrains strings this repository pins; it does not apply to text a human wrote. Nothing in `src/prompt.js` is touched.
- **No draft store.** The optimizer keeps `draft` beside `committed` (L2761–2773); this brief stores one text and the capture it was saved against. Unsaved typing lives in the panel's textarea and nowhere else.

## Out of scope (explicit)
- **Every DOM change**: the read-only capture box, the editor textarea, the three buttons, the drift sentence and every string a human reads. That is brief 0043, including `janitor/panel.js`, `janitor/panel-text.js` and `janitor/main.js`.
- A custom-prompt seam matcher, a prompt baseline, macro resolution, a fingerprint or hash of the context, a diff view, a per-injection view, or any attempt to attribute part of the system message to Janitor's custom-prompt field.
- Editing, reordering, trimming or normalising Janitor's own text when no override is saved; changing where the manuscript prompt sits or when it is prepended; changing where injections are folded or their order.
- Any change to the continuation control, the lead-in, the stop array, the horizon, the rollback, the boundary records, the reconstruction, the frontier or the freeze. No state field, no `JANITOR_STATE_FORMAT` bump, no new `console` output.
- Character-scope persistence, a global (all-chats) override, a template library, multiple named overrides per chat, a "saved records" manager or a delete-all action (the optimizer's L3711–3739 manager is not ported).
- Any setting or toggle: an enable flag, an "ignore injections" switch, a scope selector, an editor-model selector, a drift-sensitivity knob.
- Blocking, refusing or altering a request because of drift; automatically re-saving the override against a new capture; clearing the override on drift, on a format mismatch, on chat change or on recompile.
- A cross-tab `storage` listener for the override key, any lock or merge for two tabs, any polling.
- A new dependency of any kind, including jsdom.
- Editing `src/**`, `PLAN.txt`, `TamperContainment/**`, `docs/protocol/**`, `docs/api/janitor.md` or `docs/api/sillytavern.md`.
