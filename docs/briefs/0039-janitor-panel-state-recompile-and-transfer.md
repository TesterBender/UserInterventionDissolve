## Goal
Three pure-ish pieces exist so that brief 0040's panel is a thin renderer with no logic of its own. (1) `janitor/recompile.js` holds a **pure rebuild loop** over `compileUnit` with this host's last-message clamp, plus a per-page pending flag: a human asks for a recompile, and the *next* transformed request on that chat discards the stored state for the chat and rebuilds it from the messages Janitor is sending at that moment — nothing triggers a generation. (2) `janitor/status.js` holds the snapshot of the last transformed request — reserved literal, finals, units, frontier words, whether the freeze happened, whether `stop` was sent or skipped, whether the envelope reported `janitor_router_enabled` — plus a drift-notice ledger that surfaces each edit-to-compiled-text exactly once per occurrence, which is this host's replacement for SillyTavern's toastr notice. (3) `janitor/portable.js` serialises the per-chat state to a JSON string a human can keep and parses one back after a format check. `janitor/transform.js` gains the recompile consumption step and the snapshot write; it gains no new console output and no new state field. `src/` is not modified, `src/recompile.js` is not imported, and nothing in this brief touches the DOM.

## In scope

**`janitor/recompile.js`** (new; no DOM, no `window`, `localStorage` only through `janitor/storage.js`):
- `requestRecompile(chatId)` and `consumeRecompile(chatId)` over one module-level string. `requestRecompile` stores the chat id; `consumeRecompile(chatId)` returns `true` and clears the flag when the ids match, `false` otherwise (including on a mismatch, which leaves the flag alone). The flag is **per page, in memory**: a recompile asked for in one tab is not a request made by another tab, and it must not survive a reload. It is not a state field and there is no format bump.
- `rebuildState(shaped, literal, state)` — the pure loop, mirroring `docs/modules/recompile.md#loop` without any of its host calls:
  - repeat: `derived = deriveFrontier(shaped, state, literal)`; stop when `derived.segments.length < 2`; `maxFrozenEnd = derived.segments[derived.segments.length - 1].start`; stop when `compileUnit(state, derived, literal, { maxFrozenEnd })` returns `null`; otherwise call `writeWatermarkInsurance(state, shaped)` and continue.
  - The clamp is the same one brief 0031 added and `docs/modules/janitor-adapter.md#freeze-at-request-build` already applies on the live path (`docs/modules/freeze.md#last-message-clamp`), for the same reason: a message Janitor's regenerate can still replace must never be partly compiled.
  - Hard bound of 1,000 iterations, as on the SillyTavern host; reaching it simply ends the loop.
  - Returns `{ spans: state.frozen.length, words: countWords(state.frozen.join(BLOCK_DELIMITER)), units: state.units.length }`. It mutates the state object it is given and returns no text; the caller decides what to say about it.
  - There is **no post-loop seal step**, for the reason `docs/modules/recompile.md#loop` already gives.
- `writeWatermarkInsurance(state, shaped)` — the post-freeze write brief 0033 inlined in `janitor/transform.js`: find the shaped message whose `extra[METADATA_KEY].id` equals `state.watermark.messageId`, then set `state.watermark.prefixHash = prefixIdentity(mes, state.watermark.offset)` and `state.watermarkText = mes`, or both to `''` when there is no such message. It is exported because it now has two callers (the loop and the live freeze branch); `janitor/transform.js` calls it instead of its inline copy, with identical behaviour — after brief 0037 the shaped `mes` is the same trimmed string the inline version read from the entry.
- `src/recompile.js` is **not** imported and must not be. It calls `getState`, `assignIds`, `saveChat` and `reservedLiteral` on a SillyTavern context, and it raises a summary line that belongs to that host's UI. `formatRecompileSummary` is not reused either; its pinned string is the SillyTavern drawer's.

**`janitor/transform.js`** — two additions, no change to brief 0037's step order and no change to the report line:
- **Step 2b, recompile.** Immediately after the state is loaded and before anything is classified: when `consumeRecompile(context.chatId)` is true, replace the working state with `freshState()` (below) carrying `literal` set from this request's literal, mark the request as rebuilding, and skip the ordinary single-unit freeze branch for this request. After the derivation inputs exist (that is, after brief 0037's rollback and brief 0036's identity steps, at the point where the live branch would call `compileUnit`), call `rebuildState(shaped, literal, state)` instead, then `saveJanitorState(context.chatId, state)` and re-derive once against the rebuilt state, exactly as the live freeze branch re-derives. Everything downstream — reconstruction, horizon, lead-in, stop, report — is unchanged.
- **Consequences of the reset, stated in the doc and accepted here**: `boundaries` and `pendingBoundaryAfter` are discarded with the rest of the state, so on the rebuilding request a message that stopped at the boundary is no longer exempt from brief 0037's rollback and may lose a trailing incomplete block. That is one trim of text the model had already been shown as frontier, never of compiled text, and it is cheaper than carrying a field across a reset that is meant to discard everything.
- **Status write.** Beside the existing `console.info`, call `setRequestStatus({...})` with the fields listed under `janitor/status.js`. The drift ids passed to `noteDrift` are the `messageId`s of brief 0036's `editedCompiledIndexes` entries, with empty ids dropped. The `console.info` line keeps brief 0037's and 0038's fields and gains nothing.

**`janitor/storage.js`** — one line: `freshState` becomes an exported function. No other change; brief 0037's `pendingBoundaryAfter` field and brief 0036's `janitorFormat` stay exactly as they are.

**`janitor/status.js`** (new; no DOM, no storage, no `src/` host code):
- A module-level snapshot object and `setRequestStatus(patch)` / `getRequestStatus()`; the getter returns a shallow copy so a renderer cannot mutate it. Fields: `chatId`, `literal`, `finals`, `units`, `frontierWords`, `froze`, `rebuilt`, `stopSent`, `routerEnabled`, `driftNotices` (array of strings), `at` (epoch ms of the write).
- `setStatusListener(fn)` — **one** listener slot, replaced by a second call, cleared by `setStatusListener(null)`. The panel is the only consumer; an emitter with a subscriber list would be an abstraction with one consumer. The listener is invoked after every `setRequestStatus`, inside a `try`, and a throwing listener is warned about once and never unsubscribed.
- `noteDrift(chatId, messageIds)` — appends one notice per id **not already noticed for this chat** and returns the number of new ones. The seen set and `driftNotices` reset whenever `chatId` differs from the snapshot's current `chatId`, so switching chat in the same tab starts clean. `driftNotices` is capped at 20 entries (oldest dropped); the cap is a module-level constant in this file, not a setting and not a shared constant.
- A notice is the message id and nothing else; the human-readable sentence around it is brief 0040's business (`docs/workflow/comment-policy.md` aside, panel text is human-facing and free, addendum §13).

**`janitor/portable.js`** (new; pure over strings, no storage, no DOM):
- `exportStateJson(chatId, state)` → `JSON.stringify({ kind: 'uid-janitor-state', chatId, exportedAt: new Date().toISOString(), state }, null, 2)`. The wrapper carries no version field of its own: `state.version` and `state.janitorFormat` are already the two versions that matter, and a third would be a third thing to keep consistent.
- `importStateJson(text)` → `{ ok: true, chatId, state }` or `{ ok: false, reason }` with `reason` one of `'unreadable'` (not JSON, or not an object), `'not-a-state'` (wrong `kind`, or `state` is not an object, or `frozen`/`units`/`frozenIds` is not an array, or `watermark` is not an object) and `'wrong-format'` (`state.version !== STATE_VERSION` or `state.janitorFormat !== JANITOR_STATE_FORMAT`). The reason is a code, not a sentence; brief 0040 maps it to text.
- **No repair, no migration, no merge.** A state that fails any check is refused whole. A state that passes is returned exactly as parsed — no field defaulting, no id re-keying, no clamping of the watermark against anything.
- The exported `chatId` is returned for display only. Importing a state exported from another chat is allowed and is the point of the feature (a manuscript restored into a re-created chat); the caller saves under the *current* chat's key.
- `portable.js` does not write to `localStorage`; brief 0040's panel calls `saveJanitorState`.

**Tests — `tests/janitor/`** (no DOM, no new dependency):
- **rebuild is idempotent and honest**: a recorded body whose history is long enough to compile several units yields, from a fresh state, the same `state.frozen`/`state.units`/`frozenIds`/`watermark` as the same messages compiled one unit per request through repeated `transformRequest` calls — the rebuild is not a different compiler;
- **clamp holds in the loop**: no cut ever consumes any part of the last shaped message, for a fixture whose last message is long enough to be a tempting cut;
- **termination**: a frontier of one segment, an empty frontier, and a frontier the rules refuse all return with `spans` reported and no hang; the 1,000-iteration bound is reachable only by a constructed input and ends the loop;
- **flag**: `requestRecompile('a')` then `consumeRecompile('b')` is false and leaves the flag set; `consumeRecompile('a')` is true once and false after;
- **the flag is consumed by the next request, not by the click**: a transform over a fixture with a seeded non-empty state, after `requestRecompile`, dispatches a body built from the rebuilt state and saves it; the transform after that one does not rebuild again;
- **rebuild discards**: the seeded state's `boundaries`, `pendingBoundaryAfter`, `watermarkText` and old spans are all gone from the saved state after a rebuild;
- **watermark insurance is shared**: the live freeze branch and the loop write the same `prefixHash`/`watermarkText` for the same input;
- **status**: `setRequestStatus` notifies the single listener; a second `setStatusListener` replaces the first; a throwing listener warns once and later writes still succeed; `getRequestStatus()` is a copy;
- **drift notices are once per occurrence**: the same id noticed twice adds one notice; a different id adds another; a chat-id change clears the ledger; the cap drops the oldest;
- **export/import round trip**: `importStateJson(exportStateJson(id, state))` returns a deep-equal state; a truncated string, a `{}`, a state with a wrong `janitorFormat` and one with a wrong `version` each return the matching `reason` and no state;
- **no DOM and no host**: no file added by this brief references `document`, `window`, `localStorage` directly, or `SillyTavern`.

**`dist/janitor-manuscript-dissolve.user.js`** — regenerated with `npm run build:janitor` and committed. Never hand-edited. New top-level names must not collide with an existing module's (`docs/modules/janitor-build.md#supported-module-syntax`); the build fails loudly if they do.

### Decisions this brief takes (do not re-open during implementation)
- **Recompile is a flag consumed by the next transformed request.** The script cannot start a generation on this host, and inventing one (a synthetic request, a replayed body) is refused. Until the human sends something, a requested recompile has not happened, and the panel says so.
- **Recompile discards state for the chat and rebuilds from the request in hand.** Janitor's own window truncation therefore bounds what can be rebuilt (`TamperContainment/PLAN-janitor.md` reality 4): messages Janitor no longer sends are gone from the rebuild. This is a cost, not a bug, and it is why Export exists.
- **Export is a JSON string, not a download.** The mechanism (a textarea in brief 0040) is decided there; this module produces the string and nothing else, so no `Blob`, no object URL and no `<a download>` appears anywhere in the script.
- **Import replaces, never merges.** There is no "combine two manuscripts" path and no partial import.
- **Drift notices live in memory.** The ledger is per page; a reload re-notices an edit that is still present. Persisting it would be a second store to keep correct for a notice whose whole purpose is to be seen once while the human is looking.
