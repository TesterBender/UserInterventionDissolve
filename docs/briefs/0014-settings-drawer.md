# Brief 0014 — minimal settings drawer: description, preset-import hint, one-click install, reserved-literal status
Status: draft
Complexity: high
PLAN sections: §8 (the hard boundary is keyed to the bare reserved tag literal `Mara:`, derived from the externally authored character — the drawer displays that literal so the collaborator can see which tag is protected, and nothing else about it), §23 (host requirements: "enforce a hard external-character boundary" and "merge external text into manuscript-bearing context" are behaviours, not settings — the host list contains no configuration surface, which is why this drawer configures nothing)
Invariants touched: INV-2 (the drawer *reports* the reserved literal; it must never let anyone set, override or store it), INV-9 / `docs/protocol/invariants.md#enforcement-model` (the semantic grammar is carried by the prompt text, which is why the only action in the drawer is installing the preset that carries it)

## Goal
SillyTavern's Extensions panel gains one drawer for this extension containing exactly four read-only-or-single-action elements: a two-sentence description of what the extension does, a hint naming the README's manual preset-import steps, an "Install reference preset" button that writes the bundled chat-completion preset to disk through `getPresetManager('openai').savePreset(...)`, and a status line showing the currently reserved tag literal (`<persona>:`). The preset object the button saves is built from the same frozen template the checked-in `presets/*.json` files are generated from, moved into a browser-safe `src/preset-template.js` so the generator, the staleness test and the button share one source. Nothing in the drawer is a toggle, a text field, a select, or a stored setting; the extension's behaviour is identical whether or not the drawer was ever opened.

## Preconditions

Do not write a local copy of the persona/literal derivation, and do not add a fallback that reimplements it — `boundary` owns INV-2's literal (`docs/briefs/0008-boundary-module.md`).

## In scope
- **Move the preset template into browser-safe module `src/preset-template.js`.** It exports, unchanged in value: the frozen `TEMPLATE` object, `buildPresets()` (same return shape `{ '<filename>': <object> }`, same deep-clone-per-call behaviour), plus two new named constants `PRESET_NAME = 'Manuscript Protocol'` and `OPENAI_PRESET_FILE = 'Manuscript Protocol.json'` so the button, the generator and the tests cannot drift on the name. It imports **only** `MANUSCRIPT_SYSTEM_PROMPT` from `./prompt.js` — no `node:fs`, `node:path`, `node:url`, no `process`, no top-level side effect, nothing that would fail when loaded by a browser as an ES module from disk. The four existing pointer comments on the template/`buildPresets` move with the code and keep citing their current `docs/modules/preset.md` anchors.
- **`tools/build-preset.mjs` becomes the writer only**: keeps the shebang, the `node:fs`/`node:path`/`node:url` imports, `ROOT`/`PRESET_DIR`, the entry-module guard and the write loop; imports `buildPresets` from `../src/preset-template.js` and re-exports it (`export { buildPresets } from '../src/preset-template.js';` or an import + `export`) so any existing importer keeps working. No behaviour change: `npm run build:preset` still writes byte-identical files and still writes nothing when imported.
- **Create `src/ui/settings.js`** exporting three functions and no module-level DOM work:
  - `renderSettings(ctx)` → the root element, or `null` when no container exists. Container lookup is `document.getElementById('extensions_settings2') ?? document.getElementById('extensions_settings')`; return `null` and append nothing if both are absent (aesthetic/real-install reference for the shape and the fallback: `Intercede:src/ui/settings.js:143-145`). Idempotent: if an element with the root id is already in the document, return it without building or appending a second one.
  - Built with plain DOM APIs (`document.createElement`, `textContent`, `append`) — **no jQuery, no `innerHTML`, no template string of markup**. jQuery is present on a real install (`Intercede:index.js:308` branches on `globalThis.jQuery`), but plain DOM avoids depending on it and keeps the jsdom test free of a shim. All text is set with `textContent`.
  - Structure and classes: root `div.uid-settings` (id `uid_settings`) → `div.inline-drawer` → `div.inline-drawer-toggle.inline-drawer-header` containing `<b>` with the display name and `div.inline-drawer-icon.fa-solid.fa-circle-chevron-down.down` → `div.inline-drawer-content` holding three `div.uid-settings-section` blocks. ST's own classes (`inline-drawer*`, `menu_button`) are host classes and are used verbatim; every class we author is `uid-`prefixed. Visual register copied from `Intercede:src/ui/settings.js:31-38` and `Intercede:style.css:426-476` as *aesthetic reference only* — no Intercede code, markup string, or class name is copied (`docs/decisions/0002-structure-from-intercede.md`, user ruling: aesthetic only).
  - Section 1 — description: one `div.uid-settings-heading` and one `div.uid-settings-note` with at most two sentences saying what the extension does (a continuous manuscript in tagged blocks; the externally authored character's tag is reserved and generation stops before it). No feature list, no version string, no links.
  - Section 2 — preset: a `div.uid-settings-note` naming the manual route in the verified label order — **AI Response Configuration** → **Chat Completion Presets** → **Import preset** → `presets/Manuscript Protocol.json` — and saying the README has the same steps (`docs/api/sillytavern.md#preset-openai-import-ui-path`, README §"Import the reference preset" from brief 0005). Then `div.uid-settings-actions` holding one `button.menu_button.uid-install-preset` (id `uid_install_preset`, `type="button"`) labelled "Install reference preset", whose `click` listener calls `installReferencePreset(ctx)` and swallows its rejection (the function never rejects; the listener still guards).
  - Section 3 — status: one `div.uid-settings-heading` plus `div.uid-settings-status` (id `uid_reserved_literal`), populated by calling `refreshReservedLiteral(ctx)` once at the end of `renderSettings`.
  - `installReferencePreset(ctx)` — `async`, returns `true` on success and `false` on any failure, never throws. Steps, in order: `const manager = ctx.getPresetManager?.('openai')`; if it is nullish or `typeof manager.savePreset !== 'function'`, notify an error and return `false`. Otherwise `await manager.savePreset(PRESET_NAME, buildPresets()[OPENAI_PRESET_FILE])` — exactly two arguments, no options object (`docs/api/sillytavern.md#preset-programmatic-save`). On resolve: success notification whose text tells the collaborator to select **Manuscript Protocol** in the **Chat Completion Presets** dropdown (saving does not activate it), return `true`. On reject: `console.error` with `LOG_PREFIX` and an error notification, return `false`.
  - `refreshReservedLiteral(ctx)` — finds `#uid_reserved_literal`; returns without error when it is absent (the drawer may never have rendered). Sets `textContent` to `Reserved tag: ${literal}` where `literal = reservedLiteral(ctx)`, or, when `reservedLiteral` returns `''`, to a fixed no-persona sentence stating that no persona name is set and nothing is reserved. Recomputed per call, never stored (`docs/api/sillytavern.md#getcontext`).
  - Notifications go through one module-local helper using `globalThis.toastr?.[kind]` with a `console` fallback when `toastr` is missing, so an absent global cannot throw (shape reference: `Intercede:src/utils.js:85-92`).
  - The module must not contain the string `SillyTavern` (`tests/bootstrap.test.js:163-168` scans `src/`), must not read or write `extensionSettings`, and must not call `saveSettingsDebounced` — there is no setting to save.
- **`index.js`** gains exactly three lines of wiring: one `import { renderSettings, refreshReservedLiteral } from './src/ui/settings.js';`, one `renderSettings(ctx);` call at the end of a successful `init()` (after `ready = true`), and one `refreshReservedLiteral(getCtx());` as the **first statement** of the existing CHAT_CHANGED handler, before its nullish-`chatId` early return (the persona may have changed with the chat, and the status must stay honest even when no chat is open). No other change to `init()`, the interceptor placeholder, or the state-materialisation block.
- **`style.css`**: replace the empty `.uid-root` rule with a small set of `uid-`prefixed rules and nothing more — `.uid-settings .inline-drawer-content` (column flex, 6px gap), `.uid-settings-section` (column flex, 6px gap) and `.uid-settings-section + .uid-settings-section` (14px top margin), `.uid-settings-heading` (0.85em, bold, uppercase, 0.04em letter-spacing, `var(--SmartThemeEmColor, rgb(145, 145, 145))`), `.uid-settings-note` (same muted colour), `.uid-settings-actions` (flex, `justify-content: flex-end`, 8px gap, top border `var(--SmartThemeBorderColor, …)`), `.uid-settings-status` (monospace font-family so the literal reads as a literal), `.uid-settings .menu_button` (`width: auto; white-space: nowrap`). Every colour is a `var(--SmartTheme*, <fallback>)`; no fixed background, no `!important`, no `@media`, no animation, no `#id` selector.

It builds its own plain-object fake context locally (`tests/helpers/fake-context.js` is out of bounds for this brief) except in the one index-level case, which uses `installFakeContext()` after inserting `#extensions_settings2` into `document.body`.
- **`tests/preset.test.js`**: change the `buildPresets` import to `../src/preset-template.js`, and extend the single "is not imported by the generator" case to assert `CONTINUATION_CONTROL` appears in neither `tools/build-preset.mjs` nor `src/preset-template.js`. ## Out of scope (explicit)
- **Any toggle, checkbox, select, slider, text field, or persisted setting.** No enable/disable switch, no "reserved character" override, no preset-name field, no verbosity/debug control, no `extensionSettings` read or write, no `SETTINGS_KEY` usage. Decision 0002's user ruling and PLAN §23's host list are the authority; a second element in the drawer is a scope breach, not an improvement.
- Activating the preset after saving it: no `/preset` slash command, no `executeSlashCommandsWithOptions`, no write to `oai_settings`, no `OAI_PRESET_CHANGED` handling. The button creates the file and updates the dropdown (`#preset-programmatic-save`); choosing it stays the collaborator's act, and the toast says so. (`#preset-slash-commands` exists and is deliberately unused.)
- Installing the sysprompt/text-completion template (`presets/manuscript-protocol.sysprompt.json`) programmatically, a second button, an "uninstall"/"remove preset" action, an overwrite confirmation dialog, a version/staleness check against an already-installed preset, or a "preset installed ✓" indicator.
- Fetching the shipped JSON over HTTP from the extension's own URL. The template import is the single source of truth and needs no network; do not add `fetch`, `import.meta.url` path juggling, or a manifest asset path.
- Editing the preset object before saving: no persona substitution, no `{{user}}` expansion, no injected reserved literal, no extra `prompts[]` entry, no sampler or connection keys. The saved object must deep-equal the committed `presets/Manuscript Protocol.json` (brief 0005's whole point).
- The frontier editor, the seed-entry dialog (§19), a modal helper, a wand-menu entry, a per-message button, a toolbar, or any second UI surface. Decision 0002's four-surface minimum lists them; this brief delivers exactly one of the four.
- A shared `src/ui/` framework: no `open.js` dispatcher, no `modal.js`, no component/render abstraction, no event bus, no `globalThis.<Ext>` diagnostics surface. One file, three exported functions.
- Any i18n/`data-i18n` attributes, any `manifest.json` change (`css` is already declared), any dependency, any change to `package.json`, `eslint.config.js`, `vitest.config.js` or `tools/check-comments.mjs`. If the implementer finds the `check:comments` script glob does not reach `src/ui/settings.js`, they must **report that to the orchestrator** and satisfy Acceptance by invoking the checker directly — not edit `package.json`.
- Touching `src/prompt.js`, `presets/*.json` (they are regenerated, never hand-edited), `src/boundary.js`, `src/state.js`, `src/grammar.js`, `src/host.js`, or `src/constants.js`.
- Re-rendering, removing, or re-attaching the drawer on CHAT_CHANGED, APP_READY, or any other event; only the status line's text is refreshed.
